Features

Built for the
infra you run.

Every production failure mode Baileys ignores — handled by default.

🔄

Connection State Machine

Every disconnect code mapped to a typed handler. 401/403/405/463/515 — all handled, all recoverable where possible. Exponential backoff with configurable caps.

disconnectedconnectingreconnecting
⚡

Circuit Breaker

Trips after sustained 405 rate limits. CLOSED→OPEN→HALF_OPEN→CLOSED. Probe attempts auto-recovery. Prevents the ban spirals that kill production bots overnight.

state eventsprobe-and-recover
🗄️

Pluggable Auth

SQLiteAuthStore with WAL mode and atomic writes. MemoryAuthStore for tests. FileAuthStore for Baileys migration. One-call migrateFromBaileys().

SQLiteMemoryFileCustom
🪣

Token-Bucket Queue

Priority queue: urgent > high > normal > low. Human-like gaussian jitter. Dead-letter queue for permanent failures. 20 msg/min default — never triggers a ban.

4 priority levelsDLQjitter
🧩

Koa-Style Middleware

Composable pipeline via client.use(). Built-ins: LID resolver, anti-ban delay, message logger. Write your own handler in 5 lines.

lidResolver()antiBan()messageLogger()

Prometheus Observability

Built-in /health and /metrics HTTP endpoints. Queue depth, circuit breaker state, reconnect count, message throughput — all exported as Prometheus gauges.

Auth Stores

No more
JSON corruption.

Atomic writes. Crash-safe. Pluggable. One interface, three implementations.

★ Production

SQLiteAuthStore

WAL mode, atomic writes, crash-safe. Zero external dependencies beyond better-sqlite3. The default for any real deployment.

import { SQLiteAuthStore } from 'nexawhats/store'; const store = new SQLiteAuthStore('./auth.db'); const state = await store.loadState();
Testing

MemoryAuthStore

No persistence. Perfect for CI pipelines, unit tests, and ephemeral bots. Drop-in anywhere SQLiteAuthStore works.

import { MemoryAuthStore } from 'nexawhats'; const store = new MemoryAuthStore(); // no files · no cleanup · instant
Migration

FileAuthStore

Baileys-compatible format. Use migrateFromBaileys() to move existing sessions in one call — zero re-scan, zero QR.

await migrateFromBaileys( './auth_info_multi', store // target SQLiteAuthStore );

Quick Start

Up in
60 seconds.

Install, create a client, handle messages. That's it.

1

Install

npm install nexawhats + better-sqlite3 for the production auth store.

2

Create a client

Pass your auth store and queue config. All options have sensible defaults. Add middleware with client.use().

3

Connect & handle

Call client.connect(). First run shows a QR — scan once, session persists automatically via the auth store.

4

Listen on events

Use client.on('messages.upsert') or plug in middleware. Both patterns coexist cleanly.

index.ts
import { createClient, MemoryAuthStore } from 'nexawhats'; // 1. Auth store (SQLiteAuthStore in production) const store = new MemoryAuthStore(); const state = await store.loadState(); // 2. Create client const client = createClient({ auth: state ?? { creds: {}, keys: store }, queue: { messagesPerMinute: 20, humanLikeTiming: true }, }); // 3. Middleware client.use(async (ctx, next) => { console.log(`${ctx.senderName}: ${ctx.text}`); await next(); }); // 4. Handle messages client.on('messages.upsert', async ({ messages, type }) => { if (type !== 'notify') return; for (const msg of messages) { if (msg.key.fromMe) continue; await client.send(msg.key.remoteJid!, { text: 'Hello from NexaWhats!' }); } }); // 5. Connect await client.connect();
